## 1 测试概述

### 1.1 编写目的

为全面验证“智能共享自习室预约系统”各项业务功能、性能指标、并发安全性以及高可用降级能力，检验系统是否符合《需求规格说明书》及《概要/详细设计说明书》中界定的各项技术规范与业务规则，特编写本系统测试报告。

本报告严格基于“5 大功能模块垂直全栈分工”体系，对单元测试、接口端到端测试、高并发抢座防超卖压测以及前端构建验证的执行结果进行结构化汇总与归因分析，为系统定稿验收与答辩交付提供客观、真实、可复现的质量证据链。

### 1.2 测试范围

测试覆盖系统的全栈分层体系与 5 大业务模块：
1. **核心算法与组件单元测试**：覆盖加权分配评分纯函数、预约时段边界与粒度校验、分布式互斥锁（竞争/属主释放/看门狗续期/nil降级）、JWT 登出黑名单、Redis 旁路缓存防雪崩抖动、分布式原子限流、AI 客户端流式解析与配置容错解析；
2. **REST API 接口端到端集成测试**：覆盖游客认证鉴权、学生选座预约、全生命周期状态机流转（创建/排他/重叠拦截/超时/取消）、满座先到先得候补排队与位次计算、信用分履约流水、站内通知、空间占用运营热力图矩阵等完整业务闭环；
3. **高并发抢座与防超卖性能测试**：模拟 20 个独立学生会话在同一毫秒瞬时发起请求争抢同一座位的极值场景，验证 Redis 分布式锁与 PostgreSQL GiST 物理排除约束的“绝不超卖”零脏写特性及响应延时分布；
4. **前端构建与打包验证**：验证 Vue 3 + Vite 生产构建过程及 9 个路由页面分包完整性。

## 4 高并发抢座与防超卖性能测试（3 项）

### 4.1 测试场景设计
- **主责人员**：叶泳言（分布式锁与 GiST 排除约束设计）、王建东（并发压测脚本编排与执行）
- **测试模型**：瞬间高并发场景（20 线程瞬时发起请求）。
- **抢座目标**：20 个已激活学生账号（`stu11` ~ `stu30`，各自拥有合法的独立 JWT）在同一毫秒发起 HTTP 请求，目标抢占 **1F-静音自习室 12 号座位（2026-09-28 14:00 - 16:00）**。
- **保护体系**：
  1. 接入层：Redis 分布式锁 `studyroom:lock:seat:12:2026-09-28` 拦截重复进入；
  2. 持久层：PostgreSQL 物理排他约束 `EXCLUDE USING gist (seat_id WITH =, res_date WITH =, tsrange(...) WITH &&)` 提供原子绝对一致性。
- **判定标准**：
  - 必须且仅能有 **1 个请求成功**，返回 HTTP 200 OK；
  - 剩余 **19 个请求全部拦截**，返回 HTTP 409 Conflict（“该座位此时段已被预约”）；
  - 数据库中对应时段仅生成一条合法记录，超卖数量严格为 0。
