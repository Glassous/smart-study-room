# 1．引言

## 1.1 编写目的

本说明书依据《需求规格说明书》（SSR-REQ-001）编制，从总体上定义智能共享自习室预约系统的体系结构、模块划分、外部/内部接口、数据结构与运行方式，作为后续详细设计与编码工作的直接依据。

预期读者：系统设计与开发人员、测试人员、课程设计指导教师。

## 1.2 项目背景

a. 本项目为《系统分析与设计》课程设计课题，由 5 人项目小组自主选题开发，指导教师所在课程组为主管部门；

b. 本系统为独立 Web 应用（B/S 架构），通过浏览器向学生与管理员提供服务，不与其他业务系统存在接口依赖；数据库采用自管 PostgreSQL 实例。

## 1.3 定义

| 术语/缩写 | 说明 |
| --- | --- |
| 分层架构 | handler（HTTP 适配）→ service（业务）→ repository（数据访问）的三层组织方式 |
| 仓储模式 | Repository 模式，将数据访问细节封装在独立层 |
| 调度器 | 后台定时任务组件，负责违约扫描、候补递补、签到提醒 |

| 优雅关闭 | 收到终止信号后停止接收新请求、等待在途请求完成再退出 |

# 3．总体设计

## 3.1 处理流程

系统总体处理流程为"请求—认证—业务—落库—调度闭环"：浏览器发起 HTTPS/HTTP 请求 → Gin 路由与中间件链（CORS → JWT 认证 → RBAC）→ handler 解析参数 → service 执行业务规则（冲突检测/评分/状态机/信用规则）→ repository 参数化访问 PostgreSQL → 统一响应返回；同时后台调度器周期运行，驱动预约状态自动流转与候补递补。

# 4．接口设计

## 4.1 外部接口

**（1）用户界面接口**：前端 SPA 通过 axios 调用后端 REST API；除登录/注册与健康检查外，全部请求携带 `Authorization: Bearer <JWT>`；响应统一为 `{"code", "message", "data"}`。

**（2）软件接口（REST API 分组）**：

| 分组 | 前缀 | 主要端点 |
| --- | --- | --- |
| 认证 | /api/auth | register、login、profile |
| 房间座位 | /api/rooms、/api/seats | 房间列表、座位平面图（含时段占用） |
| 预约 | /api/reservations | 创建、自动分配、签到、离开、返回、签退、取消、我的预约 |
| 候补 | /api/waitlist | 加入、取消、我的候补 |
| 通知 | /api/notifications | 列表、未读数、标记已读、全部已读 |
| 统计 | /api/stats | heatmap、overview、trend、peak、top-seats |
| 管理端 | /api/admin | 房间 CRUD、座位 CRUD/批量生成、用户管理、统计 |

**（3）硬件接口**：无。

## 4.2 内部接口

后端各 service 间通过 Go 接口解耦，关键内部接口约定：

| 提供方 | 接口方法（摘要） | 调用方 |
| --- | --- | --- |
| AuthService | Register / Login / Profile | auth handler |
| SeatService | ListRooms / GetSeatMap / CreateSeat / BatchCreateSeats / UpdateSeat / DeleteSeat | 对应 handler、allocation |
| ReservationService | Create / AutoAllocate / Checkin / Leave / Return / Checkout / Cancel / ListMine | 对应 handler、scheduler |
| CreditService | ApplyViolation / ApplyCompletion / ApplyLateCancel / GetCredit | reservation、scheduler、handler |
| WaitlistService | Join / Cancel / ListMine / PromoteReleased | handler、scheduler |
| NotificationService | Push / List / MarkRead | 各业务 service、handler |
| StatsService | Heatmap / Overview / Trend / Peak / TopSeats | handler |

跨模块协作事件约定：预约取消/违约 → 触发候补递补；递补成功 → 触发通知与预约创建。事件在 service 层以方法调用实现（进程内直接调用，保持事务边界清晰）。

# 6．运行设计

## 6.1 运行模块的组合

启动组合：`cmd/server` → 加载配置 → 建立连接池 → 装配 repository → 装配 service → 注册路由 → 启动 HTTP 监听 → 启动调度器 goroutine。

运行期并发组合：每个 HTTP 请求一个 goroutine（Gin 管理）；调度器独立 goroutine，每 60 秒执行一轮（违约扫描 → 候补递补 → 签到提醒）。

## 6.2 运行控制

- 配置通过环境变量注入（STUDYROOM_PORT / STUDYROOM_DB_URL / STUDYROOM_JWT_SECRET）；
- `/api/health` 暴露存活状态（含数据库连通性）；
- 收到 SIGINT/SIGTERM 优雅关闭：停止调度器 → 关闭 HTTP → 释放连接池。

## 6.3 运行时间

| 模块 | 预估运行时间 |
| --- | --- |
| 常规 CRUD 接口 | < 50ms |
| 预约创建（含约束检查） | < 100ms |
| 自动分配（158 座规模） | < 150ms |
| 热力图聚合（单房间 14 天） | < 800ms |
| 调度器单轮 | < 500ms |

# 7．出错处理设计

## 7.1 出错输出信息

统一响应 `{code, message, data}`；HTTP 状态码与业务场景映射：

| HTTP | 场景 | message 示例 |
| --- | --- | --- |
| 400 | 参数错误 | 开始时间必须早于结束时间 |
| 401 | 未认证/令牌过期 | 令牌无效或已过期 |
| 403 | 无权限/禁约/禁用 | 信用分过低，暂时禁止预约 |
| 404 | 资源不存在 | 座位不存在 |
| 409 | 冲突 | 该座位此时段已被预约 |
| 500 | 内部错误 | 服务内部错误，请稍后重试 |

## 7.2 出错处理对策

1. **事务回滚**：预约创建+信用变动等多表写操作置于同一事务，失败整体回滚；
2. **约束兜底**：应用层冲突检测先行，数据库排除约束最终兜底（409 语义转换）；
3. **降级运行**：统计接口异常不影响预约主链路；通知写入失败仅记日志不阻断主流程；
4. **恢复与再启动**：服务无本地状态，重启即恢复；调度任务幂等（状态条件更新），重复执行无副作用。

# 8．安全保密设计

1. 口令 bcrypt（cost=10）存储，杜绝明文/可逆加密；
2. JWT HS256，密钥经环境变量注入，令牌含 uid/role/过期时间，有效期 24h；
3. RBAC：`/api/admin/**` 强制 admin 角色，中间件统一拦截；
4. SQL 全参数化（pgx 占位符），杜绝字符串拼接；
5. 日志脱敏：口令字段永不落日志；
6. CORS 白名单限制跨域来源。

# 9．维护设计

1. **数据库演进**：backend/migrations 按序号管理，`scripts/apply_migrations.sh` 可重复执行；
2. **结构化日志**：Gin 访问日志 + 业务错误日志，含 trace 摘要；
3. **单元测试**：核心算法（分配/状态机/信用/冲突）单测覆盖，CI 自动执行；
4. **配置集中**：全部环境变量集中在 config 包，变更零散参数无需改代码；
5. **部署脚本**：scripts 目录提供集群初始化/启停、迁移、种子脚本，降低环境维护成本。
