# 1．引言

## 1.1 编写目的

本说明书依据《需求规格说明书》（SSR-REQ-001）编制，从总体上定义智能共享自习室预约系统的体系结构、模块划分、外部/内部接口、数据结构与运行方式，作为后续详细设计与编码工作的直接依据。

预期读者：系统设计与开发人员、测试人员、课程设计指导教师。

## 1.2 项目背景

a. 本项目为《系统分析与设计》课程设计课题，由 5 人项目小组自主选题开发，指导教师所在课程组为主管部门；

b. 本系统为独立 Web 应用（B/S 架构），通过浏览器向学生与管理员提供服务，不与其他业务系统存在接口依赖；数据库采用自管 PostgreSQL 实例。

## 1.3 定义

| 术语/缩写 | 说明 |
| --- | --- |
| 分层架构 | handler（HTTP 适配）→ service（业务）→ repository（数据访问）的三层组织方式 |
| 仓储模式 | Repository 模式，将数据访问细节封装在独立层 |
| 调度器 | 后台定时任务组件，负责违约扫描、候补递补、签到提醒 |
| DSN | Data Source Name，数据库连接串 |
| 迁移脚本 | 声明式 SQL 脚本，管理数据库结构演进 |
| 优雅关闭 | 收到终止信号后停止接收新请求、等待在途请求完成再退出 |

# 2．任务概述

## 2.1 目标

在需求规格说明书确定的 G1–G7 目标下，给出可实现的技术总体方案：前后端分离 + REST API + 关系数据库 + 后台调度器，保证功能完整、结构清晰、便于分工并行开发与测试。

与《需求规格说明书》2.2 节一致：服务端 Linux + Go 1.27/Gin + PostgreSQL 18；客户端现代浏览器；开发期前端 Vite 开发服务器（5173）经 CORS 访问后端（8080）。

## 2.4 条件与限制

1. 教学演示场景：单实例部署，无水平扩展要求，但结构上不得阻碍后续扩展；
2. 无外部消息网关：通知全部为站内通知；
3. 时间基准为服务器时间；
4. 小组 5 人分工开发，模块间接口需先行约定（本文档第 4 章）。

# 3．总体设计

## 3.1 处理流程

系统总体处理流程为"请求—认证—业务—落库—调度闭环"：浏览器发起 HTTPS/HTTP 请求 → Gin 路由与中间件链（CORS → JWT 认证 → RBAC）→ handler 解析参数 → service 执行业务规则（冲突检测/评分/状态机/信用规则）→ repository 参数化访问 PostgreSQL → 统一响应返回；同时后台调度器周期运行，驱动预约状态自动流转与候补递补。

## 3.2 总体结构和模块外部设计

系统采用前后端分离的四层逻辑架构：

【插图位置：diagrams/02_系统架构图.mmd —— 图 3-2 系统架构图】

- **客户端层**：Vue 3 单页应用（Element Plus + ECharts + Pinia），负责界面呈现与交互；
- **接入层**：Gin 路由 + 中间件（CORS、JWT 认证、RBAC、日志），承担协议适配与安全准入；
- **业务服务层**：9 个 service 模块（认证、房间座位、预约、生命周期、自动分配、信用、候补、通知、统计）+ 1 个调度器；
- **数据访问层**：repository 封装全部 SQL；PostgreSQL 提供持久化与排除约束兜底。

后端模块结构（包路径）：

【插图位置：diagrams/10_模块结构图.mmd —— 图 3-3 后端模块结构图】
